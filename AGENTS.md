# UI Contract Studio — Agent Rules

This file contains only the **current rules**. Detailed procedures are documented in the [Pi skill](.pi/skills/ui-catalog/SKILL.md) and [guides](docs/README.md); previous changes are recorded in the [changelog](CHANGELOG.md).

## 1. Source of truth and UI boundaries

- Before generating screens, consult `pi-catalog/contracts.json`, `src/ui-catalog/contracts.lock.json`, `src/ui-catalog/catalog.ts`, `src/ui-catalog/extensions/catalog.ts`, and `src/ui-patterns/`. The active catalog is closed and contains base types and extensions; **do not infer contracts from their appearance or from installed TSX files**.
- Screens generated by Pi must be **JSON only**, saved to `src/ui-screens/<slug>.json`, with metadata in `src/ui-screen-meta/<slug>.json`. Arbitrary JSX/HTML is forbidden in screens.
- Reuse approved JSON patterns and active types. Check `pi-catalog/retired-contracts.json` before choosing a type. Do not restore retired galleries or types.
- ReUI, installed shadcn/ui components, and demo code are **not** automatically Pi types. Explorers are fixed inspection tools, not agent-generated components.

## 2. Contract and data security

- JSON must contain only types, properties, slots, events, and actions explicitly defined in Zod. JSX, HTML, callbacks, unrestricted `className`, arbitrary styles, credentials, cookies, endpoints, and unapproved URLs are forbidden.
- For remote data, use only a declared `sourceId`. The `processos-api` example **does not provide a backend**: authentication, authorization, user/tenant scoping, and query validation belong to the real server.
- Changes to `nodeProps` and `content` must respect keys exposed by the manifest; they must not replace node types, actions, handlers, links, sources, or field identity.
- Do not modify `src/globals.css`, `src/index.css`, or the app shell to bypass a contract without justification and review. Preserve accessibility, responsiveness, themes, and loading/error/empty states.

## 3. Changing or admitting components

- First check for an approved equivalent. A genuine gap requires **admission with a Zod schema + React component + registry**, provenance and license in `sources.json`, version/fingerprint in `contracts.lock.json`, examples, tests, and independent review. An agent **must not self-approve** its own change.
- For static compositions, edit templates and `generated-manifest.json`, run `npm run composites:generate`, and never manually edit `src/ui-catalog/extensions/generated/`. Compositions with their own state need an explicit React implementation and typed adapter.
- Generating or installing shadcn/ui code does not automatically change the catalog; verify provenance in `shadcn-plan.json` and run `npm run shadcn:verify`. Schema, prop, or event changes require migration of screens, patterns, manifests, and tests.

## 4. Generating and validating with Pi

1. Generate real schemas with `npm run pi:zod-schema`; select **only the required types** using `npm run pi:context -- --types=Card,Button` (up to 25 per batch). Do not generate with `--metadata-only`.
2. Use only `propsSchema`, examples, events, and actions from the selected context, preserving canonical property names.
3. Validate the spec using `npm run pi:validate -- --file=<arquivo.json>` and resolve `issues[].pointer` before proposing a merge.
4. Paid/live agent evaluations are **manual** and require explicit consent (`PI_EVAL_CONFIRM=yes`; repair also requires `PI_EVAL_REPAIR_CONFIRM=yes`). Never fabricate outputs or evidence.

## 5. Definition of done

- Run `npm run test:offline`, `npm run docs:check` for documentation changes, `npm run validate`, and `npm run build` when an environment is available; run contract- and generation-specific tests as appropriate.
- The full E2E suite is **manual on the main branch** through GitHub Actions; locally, `npm run verify` includes Playwright. A visual audit requires **real** screenshots and review, not an inventory or automatic approval from pixel differences.
- Report which tests actually ran, failures, and limitations; do not claim build, Playwright, real Pi evaluation, or visual certification without evidence.
- `sources.json` and `contracts.lock.json` are review records, not proof of human approval. Branch protection and independent review must be enforced on the Git platform.
